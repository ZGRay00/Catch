# PokéCatch 自动助手

适用于 [PokéCatch](https://pokecatch-online.netlify.app/) 的 Tampermonkey 用户脚本。当前版本 **4.6.0**。

[安装 / 更新脚本](https://raw.githubusercontent.com/ZGRay00/Catch/main/pokecatch-helper.user.js) · [CDN 备用安装](https://cdn.jsdelivr.net/gh/ZGRay00/Catch@main/pokecatch-helper.user.js) · [完整压缩包](./releases/pokecatch-helper-v4.6.0.zip) · [使用说明](./使用说明.txt) · [源码与构建](./pokecatch-helper/README.md)

在「运行实况 → 目标与收益」查看补图路线，点击缺少的宝可梦即可查获取条件。「图鉴」可搜索火神蛾或保姆曼波，查看燃烧虫赠蛋的天气与徽章要求，或五处水纹地点。野生刷闪覆盖每日轮换遇敌表；队列切换会重新计时游荡搜寻，保留整次运行的预算和原循环。

「培育屋 · 闪蛋计数」显示已生成蛋的闪色依据，并区分已核对构建的条件预测与参考结果。

4.3.1 修复切换标签页后补练误报页面超时的问题。需要在其他标签页使用期间持续推图时，可启用完整包中的「PokéCatch 保持激活」。[后台运行设置](./pokecatch-keep-active/使用说明.txt)

## 安装和更新

1. 在浏览器中启用 Tampermonkey，打开上面的脚本链接并确认安装。
2. 进入游戏或刷新游戏页，确认助手面板显示 `4.6.0`。
3. 后续点击面板顶部“在线更新”。发现新版后再次点击“安装新版”，在油猴确认安装，完成后刷新游戏。

从旧版手动复制安装的用户，需要先安装这一次新版。脚本也配置了油猴原生 `@updateURL` 和 `@downloadURL`。

更新按钮优先校验 GitHub 最新提交中的完整脚本，并打开同一提交的安装链接。检查失败可重试；检查和下载不会执行远程代码，不会清空当前任务或游戏存档。

## 功能

- 基础形态进化链补图鉴、指定普通野生宝可梦刷闪、目标练级与金币地图收益比较。
- 手动或智能配队、等级不足先补练、免费且无分支的等级进化、伙伴和树果支持。
- 每日团体战、指定传说捕获、轮换形态和精英阶级挑战。
- 指定游荡捕获：追踪原生地图位置，已生成的目标节点优先，错过或捕获失败后从原生入口重新进入。
- 地下通道配队、派遣、等待归队、领取确认与按预算开启晶洞。
- 自动收蛋、繁殖、对战塔、糖果工厂、世界首领、资源预算及任务队列。

## 3.4.1：成熟蛋优先领取

- 成熟蛋优先于地下归队和新的免费进化，尽早释放孵化器位置。
- 普通战斗、补练和刷取期间可切到培育屋孵化，不再等待战斗结束，领取后返回原任务。
- 已开始的事务、手动控制、真正待选择事件、独立活动、配队和道具确认仍先处理。领取期间出现新选择会返回冒险页，手动队伍的防自动补队保护保留。

## 3.4.0：配队确认、导航恢复与决策说明

- 冒险配队每次拖放后等待原生存档确认，10 秒内不重复交换；单步最多 3 次，未确认则返回冒险并暂缓 5 分钟，后续重新评估。
- 切页增加渐进重试和 60 秒有效操作时限。入口延迟加载可恢复；切换失效会暂停并给出具体原因，原生锁定条件保留等待。
- 切页占用页面事务，不被新的后台领取抢占；手动接管、停止和队列切换会清理旧请求。后台时间不消耗切页或拖放的确认窗口。
- 执行卡新增“路线与配队依据”，展示实际路线、目标地图、补练返回目标、PC 选定阵容、实际行进阵容和选择原因，支持手机展开。

## 3.3.2：任务恢复和自动化检查

- 刷钱、练级、道具、图鉴和野闪等待原生战斗或选择时先返回冒险页，推图准备现成队伍时同样处理。
- 补图鉴和野闪核对当前实际章节后才复用目标地图，避免手动切图或原生进度改变后继续停在错误路线。
- 孵蛋、进化动画上方出现新捕获回执或已识别的信息卡时，先处理上层卡片；未识别的选择保留手动处理。
- 切回前台时保留团体战准备、传说入口探测、工厂拖放确认及首领结算的剩余操作窗口，原生计时不变。

## 3.3.0：并行任务与后台服务

| 任务 | 调度方式 |
| --- | --- |
| 推图、刷钱、练级、刷道具、补图鉴、野闪、游荡 | 共享一个冒险路线，按顺序规划；同场自然产生多种收益 |
| 团体战、传说战、精英联盟、塔、工厂、世界首领捕获 | 共享一个活动槽，按顺序挑战 |
| 已配置寄养、孵蛋、已派地下队伍的计时 | 可与前台任务并行 |
| 收蛋、地下归队领取、进化、道具和页面操作 | 在安全节点依次处理，完成后返回主任务 |
| 检查在线更新 | 独立网络请求，可以同时检查 |

世界首领护盾攻击在游戏机制上不占冒险活动槽；当前助手仍按独立流程提交攻击。

- 新增任务执行卡，区分实际前台、后台原生计时、成熟待办、等待原因与页面操作归属；队列明确为串行，最小化持续更新待办摘要。
- 自动收蛋和地下归队领取优先于新的免费进化，公平轮换；副任务完成后让主任务先调度，已达标主任务不再开启新领取。
- 默认开启后台地下归队领取：只领取已派出并返回的队伍，确认全部原 UID 回到 PC 后计数。不新派遣、不开晶洞、不挪用主队或 Buddy。
- 后台领取状态独立于主任务队列，停止和刷新后先核对已开始的事务；返回页面后继续原任务，不重放旧队列中的副任务。
- 原生孵蛋和地下领取可能自动补满不足六人的冒险队。手动配队且不足六人时，后台领取暂缓并显示原因，以保留手动阵容；独立繁殖/地下主任务保留原生行为。

## 3.2.0 的主要改进

- 地下派遣和领取等待实际存档确认，兼容旧槽位记录；只有原队员真实归队后才累计领取次数，避免重复派遣或误计。优先领取，达到每日次数、槽位或任务总数限制后等待；单颗晶洞可正确开启。
- 新增八种游荡目标：雷公、炎帝、水君、拉帝亚斯、拉帝欧斯、艾姆利多、龙卷云、雷电云。按对应地区冠军与解锁条件规划，沿用智能 / 手动冒险队与补练，捕获登记确认后完成。
- 传说目标核对轮换形态与精英入口。游荡目标在传说列表选择普通捕获时，也会委托在线追踪；补图鉴列表会提示选择游荡任务。
- 在线更新使用本仓库作为固定发布源，限制更新访问域名，校验脚本身份、版本与完整正文，避免旧缓存与错误脚本。

游荡遭遇仅在游戏在线逻辑中产生，普通传说战与游荡目标均不能用于刷异色。游戏会自动为游荡捕获使用库存大师球，因此助手默认等待明确授权后才主动追踪；停止助手不会暂停游戏已经发生的战斗。自动树果仅使用库存并遵守既有道具份数预算。
