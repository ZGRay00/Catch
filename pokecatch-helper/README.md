5.1.4 修复了切换标签页或从浏览器返回后按旧进度重复采购的问题。接管任务会重新读取原页面保存的队列、预算和订单。预算输入无效或保存失败时会保留输入，修正并保存后即可开始任务。导入配置时会指出具体哪一项预算有误。

「购买后使用」会在买进化道具前核对成员的当前形态和原生进化选项。一个目标完成进化后，下一份会重新检查。需要保留道具给其他成员时可选择「只购买」。

冒险配队会估算伤害浮动、命中率和击倒对手所需的回合。游戏自动换人开启时，助手也会比较阵容顺序，因为原生系统在多个队员同样合适时会优先选排在前面的成员。

练级和主线补练按可获得的 EXP/分钟比较地图。在「运行实况 → 目标与收益」可以看到当前地图比前后相邻的可刷地图快多少，以及常规换图需要的收益提升。两图各有至少三轮有效实测且平均经验都大于零时，换图门槛从 15% 降为 5%。队员学会新攻击招式后重新采样。旧版保存的 ×2 速度设置按游戏规则转为 ×1，可在设置中改选 ×3。

跨地区推图时，「本次金币净增」合计当前钱包和暂存钱包。恢复旧版任务时，如果缺少跨区总余额的起始记录，面板从恢复时重新计数并标明「重计后金币净增」。

练级和主线补练可在普通战斗期间更换训练搭档。当前搭档达到目标等级或上限后，助手从仍可获得经验、已实际出战的培养对象中选择等级最低的一只。「设置 → 配队与自动化」可单独调整经验搭档和战斗内换人。

地下主任务和神奥后台派遣默认从最高已解锁起点出发。领取归队结算后，历史纪录达到 25、50、75、100 层会分别开放该起点。跳过楼层没有经验和掉落，可关闭自动最高并填写手动上限。旧版自定义的高于 1 层的上限会保留。配队会参考派遣位的探险主题和首个守卫，运行实况分别显示当日额度与累计派遣。

开启「每日团体战优先」后，普通冒险和主线补练也会检查每日异色团体战。助手暂存补练目标，完成挑战或当天没有可打目标时恢复原任务。开关旁显示最近一次检查结果。

主线补练在首次选图、队伍成长或战败避让时分批比较经验收益，选定路线前会重新核对队伍与地图条件。团体战的同伴评分复用本场首领和已选成员的计算结果。图鉴路线先显示每张地图的目标数量，展开后查看物种；登记捕获后会更新受影响的路线。

首次比较跨地区或含联盟的大型地图列表时，助手分批评估金币和经验收益。打开「运行实况 → 目标与收益」可以看到计算状态，所有候选评估完毕后才会展示排名、决定目的地。只查看榜单也能使用此功能。

补练途中的目标复评、带练队伍重排、糖果工厂配队和地下派遣也支持分批计算。助手会记住出发时的练级阵容和解锁进度，途中升级或开放新地图后可及时重新选图。盒中免费等级进化的候选评估可与推图交替执行，道具和分支进化仍由玩家选择。

野生刷闪会按游荡天气实际结束时间查找出没窗口。地区天气预报先显示各时段匹配的地区，展开后加载地图明细。

补图鉴、野生刷闪、刷钱与练级分别复用各自的路线排名，捕获、队伍成长、天气或实测收益变化时重新评估。面板合并重复刷新。盒子达到 24 只时，自动冒险配队和推图前的补练评估会分批计算，期间仍可手动接管。

在「运行实况 → 天气」选择一种或多种天气，查看本时段及随后 6 或 24 小时的匹配地区。展开时段可按地区查看具体地图。默认只看已解锁地图，可切换为全部地区。补图鉴与野生刷闪任务中的「查看地区天气预报」可带入当前所选天气，查询筛选独立保存。

补图鉴和野生刷闪可分别勾选多个搜寻地区、地图天气和目标物种。同类条件取任一匹配，三类条件同时生效。补图鉴不选物种时按基础形态收集，指定物种后逐只按实际形态登记。刷闪会跳过已有的目标异色，直至全部捕获。

图鉴可查九种化石宝可梦的复原与地下探险条件。补练和商店会显示重要进化道具的首次领取途径。采购数量按已确认的购买份数统计。

补图鉴任务的「目标与收益」显示候选地图和缺少的物种，点目标即可查看获取途径。图鉴按当前可用条件列出来源。野生刷闪选图会识别轮换地点，保留低于 0.01 次/轮的精度。切换队列任务时重新计算该任务的搜寻计时，继续沿用本次运行的支出和起始金币。

在「运行实况」的图鉴中可以按中文名、英文名或全国编号查获取途径。合众的摇草、尘土、水纹和桥影已纳入补图鉴与指定野生刷闪选图。若当前路线已生成目标可能出现的现象，助手优先保留这次遭遇。

保姆曼波（594）会出现在龙螺旋之塔章节和巨人洞窟章节的指定水纹。火神蛾（637）由燃烧虫（636）在 59 级进化。取得合众冠军徽章后，在古代城章节的大晴天经过沙漠地带的道具节点，有机会获得一次性燃烧虫蛋，需要一个空孵化位。图鉴分别显示进化链完成状态与所查物种的捕获记录。

在「运行实况 → 培育屋 · 闪蛋计数」查看每枚蛋的判定依据。已生成的蛋显示存档结果或按已核验构建计算的结果；下一枚自然蛋显示当前亲本、蛋号和待用树果条件下的预测。缺少必要数据时会显示原因，有足够信息时仍会给出机制概率。

「正在补练」按成员的实时形态显示等级与进化状态。多人同时可以免费进化时，优先处理当前补练目标。配队评估只计入可自动完成的等级进化；战力与培养成本相同时，优先培养后续进化未被道具锁住的成员。面板会提示对应道具是否持有或已解锁购买，道具与分支进化由玩家手动完成。

要在使用其他标签页时继续自动推图，在 Chrome / Edge 的扩展管理页启用开发者模式，加载完整包里的 `pokecatch-keep-active` 文件夹，在游戏页点扩展图标并选择「在当前游戏页开启」。绿色 ON 表示已连接；Chrome 会显示调试提示。此扩展使用浏览器的焦点模拟，与 `pokecatch-helper/extension` 的轻量后台支持任选一种。电脑休眠或浏览器强制冻结期间会等待恢复。普通标签页切走也会保留正在运行的任务。

「设置 → 配队与自动化 → 助手主动换人」默认关闭。游戏自带的自动换人优先。在游戏关闭自动换人、助手开启智能配队时，此开关允许助手在普通冒险单打仅剩最后一个对手时，按剩余体力、实际招式、速度与天气选择替补。游戏会将选中的成员移到队首。手动指定出战者、异色遭遇和独立活动都由原有流程处理。

对照测试统一候选等级，分别覆盖关卡等级上限与 Lv.100，并使用该等级实际可达的最终形态。实战依据存档中的成员与招式；培养预测仍遵循用户的免费进化设置。

推图配队会单独评估本章馆主的实际阵容。即使队伍能顺利打过沿途野怪，遇到多名替补扛不住馆主招式时，也会考虑从电脑换入等级稍低但更耐打的成员。运行日志会列出本次调入和调出的成员。

智能配队开启时，后台地下探险等冒险队伍适配并上阵后才派遣。开启手动配队则保留自选阵容。培育屋已核对游戏构建 a5299b1690 的自然产蛋规则；遇到后续未知构建时，会显示标注来源的参考预测，闪蛋统计仍只收录可核对的结果。

面板分为「任务」「运行实况」「设置」。在「任务」选择目标，在「运行实况」查看路线依据、队列、日志和闪蛋统计，在「设置」调整配队、后台服务和预算，或导入导出配置。切换页面会记住上次位置；底部始终保留开始、恢复和停止等任务操作。

普通用户只需把 `dist/pokecatch-helper.user.js` 安装到 Tampermonkey。模块目录是可维护的源码，不需要上传到游戏页面，也不需要安装 Node 才能使用助手。

4.1.0 新增独立“培育屋 · 闪蛋计数”卡片：当前闪蛋、成熟倒计时、原生累计孵化、本段观测与已确认闪孵分别展示。按真实亲本池、共享蛋序号和一次性靛莓果显示下一自然蛋及条件下闪序列，支持原生孵化器标记、最近记录、导出和本地清零。停止助手和手动孵蛋时也可观测；详见 [4.1 培育屋说明](docs/NURSERY-4.1.md)。

面板“在线更新”支持 GitHub Raw、jsDelivr、Fastly、GCore 和 GitHub 文件 API 五个固定来源，自动切换或手动指定。展开“更新源与连接状态”查看失败原因、版本与耗时；检查中再次点击可取消。取得最新提交时优先使用固定提交链接；只能访问分支缓存时会明确提示，多个源比较版本后再判断。

GitHub 文件 API 直接提供经校验的脚本下载。自动复查同一提交且当前为相同或更高版本时，会复用本页已校验的正文，并重新连接上次失败的来源。手动指定来源会重新联网。

安装页打不开时，可点击“下载已校验脚本”，把下载的 `.user.js` 用油猴导入。原生 `@updateURL/@downloadURL` 继续保留 GitHub Raw；油猴元数据仅支持一组地址，多源切换由面板负责。旧版只有单源，需先安装这次本地或备用 CDN 脚本并刷新，之后使用新的多源检查。

脚本在浏览器中读取游戏状态并操作游戏原生控件。队伍、任务队列和自动化设置继续使用现有存储格式；更新脚本前可以从助手面板导出诊断，游戏存档请使用游戏自身的导出功能。

在「运行实况」展开“异色概率与收集进度”，可查看当前野外和蛋的异色概率。游戏完整图鉴加成与助手的基础进化链进度分别计算。需要迁移配置时，在「设置」选择导出或导入。导入前先停止当前任务，导入后可检查队列再开始。

后台支持默认关闭。需要时先按 `extension/README.md` 加载可选扩展，手动刷新已打开的游戏页，然后点击扩展图标开启后台支持。防止系统休眠是另外一个默认关闭的选项，仅在用户勾选时申请 `power` 权限。助手的任务状态卡会显示是否检测到保活心跳。

## 开发与构建

使用 Node.js 22 或更高版本。工程没有第三方依赖，不需要执行 `npm install`。

```powershell
cd pokecatch-helper
npm run build
npm run check
npm test
npm run package
```

如果 Windows PowerShell 的执行策略拦截 `npm.ps1`，使用 `npm.cmd run build`、`npm.cmd test` 等同名命令即可，无需更改系统执行策略。

- `build` 校验模块、数据和 JavaScript 语法，然后生成工作区根目录 `Pokecatch自动助手.user.js`，以及 `dist/` 中的安装脚本、更新元数据和构建哈希。
- `check` 重新计算全部产物并检查是否与当前文件一致，不会改写文件。
- `test` 先检查构建产物，再运行本工程的构建测试和工作区 `tests/pokecatch*.test.cjs` 离线回归。
- `package` 构建并检查产物，生成 `dist/pokecatch-helper-v4.1.0.zip`。相同源码、Node 版本与 zlib 版本会生成相同字节的 ZIP。
- `test:build` 只测试构建、数据校验和打包工具；`test:browser` 运行浏览器集成回归，需要本机具有测试脚本所支持的 Chrome 或 Edge。

**修改 `src/` 和 `data/` 后再构建。根目录和 `dist/` 的 `.user.js`、`.meta.js` 及 `build-info.json` 都是生成文件，请勿手工修改。** 生成文件的改动会被下次构建覆盖，`npm run check` 会报告漂移。

`build.manifest.json` 决定模块顺序。模块在同一个 IIFE 词法作用域内依次拼接，保留现有启动保护、CommonJS 规划导出和浏览器测试钩子。浏览器安装文件仍然是完整单文件，不依赖运行时下载模块。

```text
  tools/                       导入、构建、回归入口与 ZIP 打包
  tests/                       工程完整性测试
  dist/                        可安装产物与发布压缩包
```

保留分片共享闭包，是为了兼容油猴的页面沙箱和已存在的测试。跨模块调用使用同一闭包内的声明；拆分边界不能随意移动到类或函数内部。依赖顺序和扩展方法见 [ARCHITECTURE.md](ARCHITECTURE.md)。

## 浏览器与原生机制回归

默认离线测试不会启动真实游戏或修改账户。浏览器测试使用本地模拟页面，原生机制差异测试需要另外提供**已下载的游戏公开构建文件**，不会把该文件包含在发布包中。

```powershell
node ../tests/pokecatch-helper-browser.cjs
node ../tests/pokecatch-startup-browser.cjs
node ../tests/pokecatch-execution-ui-browser.cjs
node ../tests/pokecatch-team-native-v214.cjs C:\path\to\public-app.js
```

其他 `*-native-*.cjs` 和 `pokecatch-native-*.cjs` 也是按需执行的机制核对工具，先查看对应文件参数。浏览器测试需要本机安装 Chrome 或 Edge；游戏公开构建由开发者单独取得并核对版本。

天气快照可以从已下载且已核对版本的公开游戏构建重建：`node tools/extract-pokecatch-weather.cjs C:\path\to\public-app.js`。工具使用合成内存存档与静止计时器，不读取浏览器存档、不访问网络；默认直接写入唯一数据源 `data/weather.json`，随后需要重新构建并跑天气差异回归。不要把原始游戏构建或重复的原始天气 JSON 加入发布包。

## 可选保持激活扩展

安装助手无需保持激活扩展。如果发布包有 `extension/` 或 `extensions/`，可按其中说明通过浏览器“加载已解压的扩展程序”安装。扩展属于可选支持，不能保证系统休眠、断网或浏览器强制冻结时继续执行任务。

助手后台状态和游戏原生离线收益是两套机制。页面被冻结时 JavaScript 不执行；返回页面后助手根据实际游戏状态恢复。扩展的权限与行为以其 `manifest.json` 和说明为准。

## 发布包内容与可重复构建

打包工具采用文件白名单：助手安装脚本、本工程源码和数据、开发工具、说明、与 PokéCatch 有关的测试及模拟夹具，以及存在时的第一方可选扩展。个人存档、浏览器配置、参考插件、其他游戏脚本、`.git`、缓存和已有 ZIP 均不进入发布包。

ZIP 使用固定文件顺序、UTF-8 文件名和固定时间，内置 Node `zlib` 压缩。`dist/build-info.json` 保存每份输入和产物的 SHA-256，检查时重新计算，不依赖修改时间。跨 Node/zlib 版本时压缩字节可能不同，安装脚本本身依旧可以直接比较。

## 从旧单文件迁移

`tools/import-legacy.cjs` 只用于本项目旧单文件的一次性迁移；它不会导入、运行第三方插件。迁移已经完成后，请直接编辑模块。

```powershell
node tools/import-legacy.cjs
npm run build
npm test
```

导入器会按明确的顶级声明边界切分源码，把游戏目录、天气与进化 JSON 数据独立出来，并保留原声明的执行顺序。已有模块时默认拒绝导入；`--force` 只应用于刻意重新迁移，**会覆盖模块内的修改**。它不会在日常构建和测试时自动执行。
