# 7.0.0 本地性能与网络边界基准

基线为本工作区 `1a369d0` 时的本地 6.3.14 构建产物，SHA-256 为 `356e29684b9445bef096eefa23c94b958f72f3a097dfc67d3a52b8354ccfb925`。用同一份固定种子合成输入比较前后版本，随机种子、成员分组、队伍和地图均由工具内置。夹具含普通和特殊形态、地区切换、寄养和地下队员，以及禁招、等级、口味和倍率。工具只把合成存档写进临时浏览器配置。

## 测量路径

- 读取分为取本地原文、解析和解码、首次读取、原文不变后的读取。原文未变化的解码次数单独断言。鉴于解析为同步操作，浏览器耗时也应计入这一段。
- 盒子阶段分别测量首次队伍查询、全盒签名、重复查询、单纯钱包和日志变化后的刷新、资格筛选及候选评分。精算次数直接在测试专用上下文记录 `matchupDetails` 调用，缓存命中和缺失读自生成脚本的统计。
- 搜索阶段先暖机一次，每个尺寸与目标记录七次。冷搜索清除战斗矩阵缓存，热搜索复用上一轮矩阵并替换钱包和日志字段。首份合法阵容、首份已评分阵容和最终结果分别计时。切片用测试工具每次推进约 4 ms，Node 迭代器本身没有浏览器定时器等待。
- 浏览器使用干净临时配置，在前台 Chromium 标签页加载本地夹具。比较额外计算关闭与开启时的读取、折叠和展开、页面切换、滚动、帧间隔、定时输入探针、主线程任务和总 CPU。`TaskDuration` 来自 Chrome DevTools，堆用量是检测时点采样，输入探针是定时器排队耗时。两者分别区别于物理峰值和真实触屏事件。
- 浏览器和 Node 的网络探针属于测试工具。计算、排名和导出保留所测脚本自身的实现。测得的对局、金币和经验均为合成离线模型结果。

## 基线与预算

记录于 Windows 10.0.26200、Node 24.19.0、Intel Core i5-13600KF，单位为毫秒。下表的“盒子规模”含夹具中调入寄养与地下探险的 4 只。

| 盒子规模 | 目标 | 冷搜索 p50 / p95 | 热搜索 p95 | 首份合法 p95 | 签名复用前 p95 | 最大计算片 |
|---|---|---:|---:|---:|---:|---:|
| 100 | 金币 | 199 / 261 | 90 | 3.6 | 0.15 | 11.5 |
| 100 | 学员经验 | 323 / 374 | 163 | 7.6 | 0.17 | 9.3 |
| 1,000 | 金币 | 272 / 306 | 123 | 19.3 | 0.73 | 7.2 |
| 1,000 | 学员经验 | 345 / 456 | 168 | 27.3 | 0.91 | 11.4 |
| 5,000 | 金币 | 567 / 647 | 247 | 152.8 | 6.94 | 15.0 |
| 5,000 | 学员经验 | 702 / 744 | 407 | 132.3 | 7.00 | 15.5 |

旧版稳定原文重复读取的解码次数为 0。5,000 规模改变日志与钱包后，重复签名 p95 仍需 6.68–7.24 ms。两个目标共用旧版本已保存的对战矩阵，旧版热搜索追加精算次数为 0，但热搜索依然重复搜索队伍。旧版首次纯解析与解码 p95 为 0.14–6.79 ms。按尺寸的 GC 后保留增量 p95 约为 2.83、4.06、5.86 MiB。

全池验证会比旧版短名单搜索多做工作。在比较新版之前预设本机观察线，100／1,000／5,000 的首份合法结果 CPU p95 为 50／100／250 ms，验证完成 CPU p95 为 1.5／4／15 秒，GC 后保留增量为 16／48／128 MiB。逐次报告超过 50 ms 的浏览器任务，4 ms 分片用作调度目标。观察线用来披露本机是否达标，执行质量门仍须独立满足。

## 首轮集成对照与后续比较

下列对照基于 7.0.0 首轮集成快照，SHA-256 为 `0cf98fae062b310e1422f6c4e867618f6b1f7c29a0f12ea7d364249ea77af142`。此轮单列原短名单路径和新增全池复核路径。发布前以实际候选构建的再测为准。

| 盒子规模 | 金币模式重复签名 p95，旧 → 新 | 日志变动后第一次读 p95，旧 → 新 | 短名单冷搜索金币 p95，旧 → 新 | 短名单冷搜索练级 p95，旧 → 新 |
|---|---:|---:|---:|---:|
| 100 | 0.145 → 0.001 ms | 0.19 → 0.31 ms | 261 → 294 ms | 374 → 440 ms |
| 1,000 | 0.732 → 0.001 ms | 1.64 → 2.15 ms | 306 → 502 ms | 456 → 705 ms |
| 5,000 | 6.940 → 0.001 ms | 4.17 → 11.08 ms | 647 → 686 ms | 744 → 477 ms |

每次变动存档首次读入承担了共享数据维护成本，同一份已发布快照上的重复消费者省去全盒排序。1,000 成员的短名单路径总时间在该轮仍退步，5,000 成员的练级路径变快。新增快速路径的模型平均回合变化在 0.02 以内，倒下观测和覆盖指标持平。Chrome 1,000 成员四次短名单计算总 CPU 约为 247 → 247 ms，最大帧间隔 51.2 → 48.8 ms，最大输入探针延迟 11.9 → 13.1 ms。

首轮 Chrome 1,000 成员单次完整认证为 20.49 秒墙钟、9.90 秒主线程 CPU，采样堆 122.6 MiB，记录到一项大于 50 ms 的长任务。它超过预设 4 秒 CPU 观察线。浏览器采样堆和 Node 强制 GC 后保留量口径不同。该次全池复核没有远程请求、同步入口或游戏动作，耗时结果不能用来证明手机流畅。

同一首轮构建的 Node 严格搜索中，100 夹具完成了 78 个合规成员的金币与练级复核，CPU p95 分别为 2.32 秒和 1.63 秒。1,000 和 5,000 夹具在 15.5 秒人为截止前均未完成，不能把初步队伍当作正式建议。金币 100 夹具的已验证阵容平均 1.99 回合、每场模拟倒下 0.003，对照旧版 2.05 回合、0.0057。练级输出从旧版整队成长经验改为指定学员有效经验，两个收益栏的旧新原值不能直接相减。工具另外按固定学员和相同耗时模型输出可比较的离线经验估算。

引入局部编队评分复用与先手顺序剪枝后，候选构建 `080ef0e7c206d17d907c2889809c9494fbb249799fff06196a66146793d38ea1` 同一 Chrome 1,000 成员场景单次完整验证为 8.92 秒墙钟、4.33 秒主线程 CPU、97.7 MiB 采样堆，记录到 0 项大于 50 ms 的长任务。期间夹具每秒自然写入一份无关日志，共写入 9 次。页面网络、同步与模拟游戏动作计数都是 0。当前浏览器样本仍略超 4 秒 CPU 观察线。该测量包含夹具排队和收益面板活动，单个合成样本不能视作所有设备的响应分布。

最终候选构建 `658fb8342ec88d02269698f509d9fb6a728958dfe262237dee28d5de195b737d` 以同一 Chrome、同一 1,000 成员合成夹具再测。关闭额外计算时总 CPU 约 49.6 ms、采样堆 11.6 MiB。开启完整复核时完成认证，配队墙钟 17.37 秒、总 CPU 8.48 秒、采样堆 125.7 MiB，最大帧间隔 57.2 ms、输入探针 10.8 ms、Long Task API 报告 0 个超过 50 ms 的任务。17 次本地无关日志写入期间，网络、同步与模拟游戏操作次数均为 0。该构建仍未通过提前设定的 4 秒 CPU 观察线，且本次运行慢于中间构建。帧间隔统计和 Long Task API 口径不同，二者同时保留。

同一构建以 Node 执行一次强制冷缓存金币复核，分别在预设观察线截止，未输出认证结果。进度是截止前最后一次上报，部分轮次在改良选择后从全池重新开始。此表为单样本，时间不可当作多次测量的 p95。

|---|---:|---:|---:|---:|---:|---|
| 100 | 6.7 / 64.6 ms | 1.5 s | 第 3 轮 63 / 78 | 5.6 ms | 9.1 MiB | 未完成 |

5,000 样本的计算片 p95 为 4.96 ms，累计调用对局精算 347,480 次。矩阵缓存保留量符合观察线，计算总时间未达标。严格模式可先显示未认证的合法队伍，截止、取消或依赖失效的结果仍不得当作已经验证的换队依据。

另一条不设截止的直接 Node 运行测了紧邻发布构建的金币求解器。该快照尚未包含最后一项小型地下三人队穷举认证变更，未保留独立构建散列。5,000 夹具的 3,998 名合规成员对照 292 组对手，经过 4 轮、501,568 次阵位比较完成认证，同目标模型分 1.21046。总 CPU 44.40 秒，首份合法／已评分队伍为 49.5／70.5 ms，计算片 p50／p95／最大值为 4.015／4.162／44.48 ms，GC 后堆增量 12.57 MiB。该次同样超过 15 秒计算总耗时观察线。直接 Node 计时与带 VM 隔离及计数钩子的表格各自描述对应的脚本运行方式。

发布构建 SHA-256 为 `abd6c5b730a6984541d9621e753b80273e608f602151ea16febe9130581ac5fd`。1000 只 Chrome 夹具各运行一次开关对照。测试驱动自己的 4 ms 分片时，完整复核墙钟 14.03 秒、主线程总 CPU 6.94 秒，Long Task API 记录一次 54 ms，最大帧间隔 70.5 ms。切换成助手自己的共享调度器时，完整复核墙钟 21.26 秒、主线程总 CPU 7.14 秒、结束时 Chrome 采样堆约 73.8 MiB。正常调度样本帧间隔 p95 为 20.3 ms、最大 41.6 ms，Long Task API 记录 0 次超过 50 ms，单次输入探针 3.9 ms。关闭额外计算的帧间隔 p95 为 18.1 ms，单次输入探针 10 ms。两种分片的远程尝试、云同步和夹具游戏操作均为 0。正式调度比裸分片完成得更慢，数据分别列出，单次输入探针不能推广为移动端延迟保证。

## 网络计数与复现

旧版 Chrome 157.0.8103.78 的 1,000 样本中，额外计算关闭／开启分别记录 56／247 ms 总 CPU、12.3／33.7 MiB 采样堆、输入探针最大 9.6／11.9 ms、帧间隔最大 18.3／51.2 ms，超过 50 ms 的已报告主线程长任务均为 0。Node 和浏览器测试的网络尝试、云同步入口调用和夹具游戏点击均为 0。

通过临时代理、Chrome 请求拦截与 Service Worker 绕过、页面 CSP、显式网络与原生同步探针验证。Node 隔离环境同时覆盖 `fetch`、XHR、WebSocket、EventSource、Worker 和油猴请求 API。在新旧版本各自的额外计算开启及关闭场景内，浏览器监听页面目标的 HTTP(S)、WS(S) 和 FTP 尝试。主动更新入口未调用，DevTools 的环回连接和浏览器自身的进程级流量不属于页面数据计数。本地数据与合成脚本也无法复现真实账号的游戏请求、设备休眠节流或手机输入感受。

额外用本地已有的游戏构建 `6d1e2d8d8d` 在隔离 Node VM 核对了 216 项天气伤害倍率。覆盖室外、室内、夜间与整张倍率覆盖。该脚本使用合成对象、模拟存储和禁用联网的 VM，结果独立于上述请求尝试计数。

```powershell
node --expose-gc pokecatch-helper/tools/benchmark-box.cjs $baseline 7
node --expose-gc pokecatch-helper/tools/benchmark-box.cjs pokecatch-helper/dist/pokecatch-helper.user.js 7
$env:POKECATCH_BENCH_VERIFY='1'
node --expose-gc pokecatch-helper/tools/benchmark-box.cjs pokecatch-helper/dist/pokecatch-helper.user.js 7
Remove-Item Env:POKECATCH_BENCH_VERIFY
node pokecatch-helper/tools/benchmark-box-browser.cjs $baseline 1000
node pokecatch-helper/tools/benchmark-box-browser.cjs pokecatch-helper/dist/pokecatch-helper.user.js 1000
$env:POKECATCH_BENCH_VERIFY='1'
$env:POKECATCH_BROWSER_ROUNDS='1'
$env:POKECATCH_BROWSER_QUEUE='engine'
node pokecatch-helper/tools/benchmark-box-browser.cjs pokecatch-helper/dist/pokecatch-helper.user.js 1000
```

`$baseline` 指向修改前单独保存的 6.3.14 安装脚本。`POKECATCH_BENCH_SIZES` 和 `POKECATCH_BENCH_MODES` 可覆盖测试组合。`POKECATCH_BENCH_MAX_SEARCH_MS` 可显式截止单次 Node 测量，截止时输出 `completedCold: false` 或 `completedWarm: false` 并标注临时质量。`POKECATCH_BROWSER_ROUNDS` 调整浏览器输入探针次数，`CHROME_PATH` 可指定 Chromium 可执行文件。原始输出是 JSON，包含输入条件、构建散列、计数和分位数，便于独立重算。
