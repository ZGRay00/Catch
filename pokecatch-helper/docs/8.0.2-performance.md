# 8.0.2 性能检查

对照版本为 8.0.1。测试机使用 i5-13600KF、Node 24.19 和桌面 Chrome 157。测试使用本地合成存档。各表测量的操作不同，耗时不能相加。下文的 P95 表示 95% 的样本耗时不超过该值。

## 结构

构建清单按顺序组装 52 个源码和数据片段，浏览器加载一个文件。模型计算、原生界面操作和持久化分别有独立模块。维护时耦合最集中的两处是 2,965 行的 `runtime/engine.js` 和 1,529 行的 `ui/mount.js`。前者同时管理任务生命周期和计算队列，后者同时负责创建控件、绑定事件和刷新。此次发现的重复工作正出现在这两处，分别通过任务级版本号和筛选器按需创建解决。

## 首屏和面板交互

| 操作和样本 | 8.0.1 | 8.0.2 |
|---|---:|---:|
| 1,000 只，注入完整脚本至面板可测量，中位数，每版 7 次 | 132.4 ms | 112.8 ms |
| 650 只，初次面板执行，中位数，每版 8 次 | 39.75 ms | 25.10 ms |
| 同一面板首次挂载的 DOM 节点 | 2,181 | 1,453 |
| 第一次打开物种筛选并完成布局，中位数 | 2.9 ms | 4.0 ms |
| 390 × 740 窄屏连续滚动，帧间隔 P95，每版 178 个间隔 | 16.7–16.8 ms | 16.7–16.8 ms |

冷启动逐次使用独立 Chrome 配置，交替运行两个版本。计时从向页面插入脚本开始，到面板完成同步布局为止，排除了文件读取和浏览器启动。首屏仍有约十分之一秒的同步工作。滚动在桌面浏览器中模拟窄屏，每 12 帧刷新一次面板，两版均未观察到超过 32 ms 的帧间隔。

游戏和天气目录合计约 1.93 MB。构建器将这两个目录嵌入安装文件，由浏览器的 JSON 解析器还原，回归测试逐字段比对源数据。首屏原先会给尚未打开的物种筛选框插入两遍、每遍 728 个选项。现在首次展开时集中创建，搜索词、任务和所选物种不变时保留现有列表。这解释了首次打开筛选框多花的约 1 ms。

## 排名、配队和轮询

以下为固定样本的严格全盒复核，每个版本每种场景运行三次，表中为中位数。冷计算从空的对局缓存开始，热计算沿用可用缓存。

| 样本和任务 | 冷计算 8.0.1 → 8.0.2 | 热计算 8.0.1 → 8.0.2 |
|---|---:|---:|
| 100 只，刷钱 | 1,214 → 1,679 ms | 825 → 892 ms |
| 300 只，刷钱 | 3,895 → 3,356 ms | 2,378 → 1,761 ms |
| 100 只，练级，自动换位 | 1,020 → 893 ms | 607 → 455 ms |
| 100 只，练级，手动顺序 | 904 → 784 ms | 450 → 377 ms |

候选队伍经常仅替换一名未出场的后备。现在每个敌人只记录本次搜索中上一次取胜时实际出战的成员及顺序，完整匹配才复用。败局和不同出场顺序重新计算。100 只刷钱样本的完整战斗模拟从 263,765 次降至 79,299 次，300 只从 379,771 次降至 138,548 次。五组对照中的队员、分数和路线排名均一致。专项测试还在自动换位开启、关闭时分别检验了 325 种阵容顺序。

上表隔离了配队算法的改动。1,000 只的快速模式冷计算为 251 → 255 ms，热计算为 70 → 70 ms，此模式未观察到提速。100 只刷钱场景在早一轮对照中为 1,250 → 1,138 ms，最终复测则变慢。两轮的模拟调用次数一致，墙钟耗时存在波动。

在 5,000 只的存档中，冒险配队计算尚未结束时，原来每次主循环都会将已缓存的盒子指纹重新写进搜索标识，标识长达 330,806 个字符。现在引擎对比完整指纹，变化时递增对应任务的版本号，搜索标识缩至 261 个字符。120 次轮询的单次中位数从 0.590 ms 降至 0.013 ms，P95 从 0.869 ms 降至 0.022 ms。单改金币时计算继续，变更禁用招式会触发重新评估。此项测量针对检查仍在进行中的任务。

## 长时间运行

用引擎自身的调度器对 1,000 只样本进行完整复核，两轮均达到已验证状态。第一轮 8.0.1 用时 13.25 秒，8.0.2 候选构建用时 13.34 秒，Chrome 均未记录超过 50 ms 的主线程长任务。第二轮颠倒运行顺序，最终安装文件用时 26.49 秒，8.0.1 用时 25.75 秒。此轮帧间隔 P95 由旧版 20.4 ms 到新版 20.3 ms，最大值由 52.4 ms 到 57.4 ms，两版各有一次长任务。每轮每版各测一次，测量存在波动，完整复核仍要等待十余秒至二十多秒，尚未观察到端到端提速。

5,000 只样本的存档原文不变时，重复读取低于 0.001 ms；仅金币改变后重新解码的中位数为 4.17 ms。独立孵蛋关闭时，模拟停机 60 秒，运行引擎和孵蛋服务的存储读写均为零。普通隐藏运行 60 秒时，未读游戏存档，执行了 10 次控制权续租和 1 次助手检查点写入。这些计数仅涵盖被测服务。

## 复测

在工作区根目录运行下列 PowerShell 命令。先解压随项目保留的 8.0.1 安装包，将第一行指向其中完整的用户脚本。冷启动工具使用临时浏览器配置，不读取个人 Chrome 配置。

```powershell
$baselineScript = '解压目录\Pokecatch自动助手.user.js'
node pokecatch-helper/tools/benchmark-startup.cjs $baselineScript 'Pokecatch自动助手.user.js' 7 1000

$env:POKECATCH_BENCH_VERIFY = '1'
$env:POKECATCH_BROWSER_ROUNDS = '1'
$env:POKECATCH_BROWSER_QUEUE = 'engine'
node pokecatch-helper/tools/benchmark-box-browser.cjs $baselineScript 1000
node pokecatch-helper/tools/benchmark-box-browser.cjs 'Pokecatch自动助手.user.js' 1000
```
