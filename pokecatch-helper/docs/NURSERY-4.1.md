# 4.1.0 培育屋与闪光蛋计数

面板的“培育屋 · 闪蛋计数”无需启动自动任务即可观察。折叠摘要显示当前闪蛋、孵化器总数和成熟待领数；展开后可查看每枚蛋的物种、序号、闪色结果、成熟倒计时、当前亲本预测、最近孵化记录和糖果库存。最小化按钮也会提示当前闪蛋数。

本次参考用户提供的插件功能，但没有执行或直接复制插件代码。判断与预测已对照 2026-11-18 公开游戏构建 `c9b850cf68 / app.84beed0145.js`，并与旧构建 `0a26d39c19` 做差分核验。

## 三种计数分别是什么意思

| 指标 | 含义 |
| --- | --- |
| 当前闪蛋 | 当前孵化器内能按原生规则确定为异色的蛋；数据不足另列“待判” |
| 本段新观测闪蛋 | 建立观察基线后，新出现的蛋身份中可判为异色的数量 |
| 已确认闪孵 | 蛋消失且游戏原生孵化增量与身份批次相匹配的异色蛋数量 |
| 游戏累计孵化 | 游戏自身 `stats.hatched` 的绝对值，包括助手安装前的历史 |
| 待核对孵化 | 原生计数增加，但无法确定对应蛋身份或闪色，不能默认算普通 |

首次安装只建立基线，不把已有蛋或原生历史计数充作“新观测”。重复刷新、动画回执、任务切换不会重复计数。计数先写入或蛋先消失的两种保存顺序会短暂等待匹配；仅蛋消失而无原生计数增加，不计为成功闪孵。野生、团体战、进化、交易和 PC 异色数量变化均不用作蛋统计证据。

统计按账号保存在助手独立键空间，停止、手动操作或刷新后仍可续接。回档或训练家种子变化会建立新的统计段，避免旧存档的闪孵数被当作当前累计。清空按钮只清助手的观测段，不删除蛋、亲本或游戏累计，也不清空任务与续跑记录。

## “距下一闪”是条件下的产蛋次数

新蛋的闪色使用原生训练家种子与全局蛋序号的确定性规则；旧蛋兼容明确的 `shiny` 标记和旧 UID 判定。数据不足、构建无法识别时不会用空种子猜测。

`pension.laid` 是下一枚蛋的共享编号，自然繁殖和赠送蛋都会占号；它不是已孵化数量。下一枚自然蛋对应位置 1，显示“再产第 N 枚”，避免把序号偏移 0 写成“等待 0 枚”。

当前预测逐号使用真实亲本槽位及原生选择规则，混合亲本不会因为其中一只异色就全部按 1/16 算。子代物种按游戏开放地区与形态规则回溯，包含玛纳霏产霏欧纳等情况。

靛莓果的待用标记只影响下一颗**自然繁殖蛋**；赠送蛋占号但不消耗它。预测不会把一次树果假设成每颗都有加成，也不会自动购买或使用树果。“全普通亲代”“全异色亲代”“下一颗使用靛莓果”是单独标注的假设对照，不是当前实况。

预测条件是亲本及其顺序不变、期间没有赠蛋等占号事件；实际状态变化后会重新计算。只显示产蛋颗数，不把它换算成保证的墙钟时间。满孵化器会阻止继续产蛋，需先领取释放位置。

## 显示与导出

“标记游戏孵化器中的闪光蛋”默认开启，仅添加可关闭的金色边框和名字。它不改变游戏存档、随机数或闪率，不会点击蛋，也不影响原有自动收蛋策略；自动收蛋仍按原设置处理成熟蛋。

“导出蛋统计”保存本段计数和最近记录；不导出训练家种子、蛋 UID 或游戏完整存档。统计与理论概率分别展示，历史闪蛋数无法从当前图鉴反推。

原生核验工具：`tests/pokecatch-nursery-native-v410.cjs`、`tests/pokecatch-nursery-wire-native-v410.cjs`；默认回归还包含模型、台账和存储隔离测试。浏览器回归使用独立临时配置及合成存档，覆盖停机、手动孵化、刷新、回档、清零和 360px 布局。
